# Корректировки перед сдачей

Дата: 2026-08-31. Статус: **утверждён**.

Корректирующий план: только то, чего не хватает или что сделано неверно.
Работа, которая уже идёт (фикс LIVE-8 и связанная с ним история с анкорами),
сюда намеренно не входит.

Тезис, вокруг которого собирается вся подача: **сделать персистентность
безопасной вместо запрещённой.** Референсный гайд советует кошелькам не
сохранять реестр и передеривать его каждую сессию, платя ~2N чтений на
пользователя; мы делаем сохранение безопасным (хеш-цепочка эпох, срез только
ниже `l1_accepted`, tombstones и откат курсора выше floor) и платим 0.03 с на
тёплой пересинхронизации.

## Ремонт дыр: что для этого нужно

Полный ре-бэкфилл стоит ~70 минут и в план не входит. Чтобы залатать точечно,
не хватает двух кусков:

1. **Проход-искатель** — одностраничный `getEvents` по всей истории, собирающий
   только карту «блок → число событий», без единого `getStateUpdate`. Это
   основной трафик бэкфилла без самой дорогой его половины.
2. **До-ингест только отсутствующих блоков.**

Последствие, которое надо учесть заранее: починка блока в глубине меняет
содержимое его эпохи, её хеш и по цепочке хеши всех эпох выше. Перерезать их
дёшево (локальная БД → NDJSON → zstd, без RPC), но пути нет:
`cut_ready_epochs` берёт `last_epoch().idx + 1` и умеет идти только вперёд.
Пока этого нет, отремонтированная БД не доедет до опубликованных байтов — ещё
один довод чинить до хостинга, а не после.

## План

Порядок: A и B независимы, C→D — единственная длинная цепочка, E параллельна
всему, F закрывается последней.

### A. Данные мейннета

1. **Прогон по дырам, не перезатяг с нуля.** Проход-искатель → до-ингест
   отсутствующих блоков → перерез эпох от первой затронутой. Полный
   ре-бэкфилл — запасной вариант, не план.
2. **Уметь перерезать эпохи назад.** Сегодня цикл идёт только вперёд от
   `last_epoch`, поэтому отремонтированная БД не доедет до опубликованных
   файлов.

Приёмка A: счёт событий сходится с цепочкой на всей истории, `verify-root`
MATCH, `epoch-verify` зелёный, и записанный после ремонта анкор подтверждается
независимой проверкой.

### B. Хостинг — минимальный набор

TLS и домен — часть деплоя, здесь их нет.
