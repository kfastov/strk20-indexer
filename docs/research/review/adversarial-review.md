## Lens: correctness

Reviewed the data pipeline on proto/keyless-indexer (indexerd db/ingest/cutter/rpc/server/compat/bridge, feed codec/manifest/mpt, client store/sync/transport) against the spec and known deltas. The codec, hash-chain verification, MPT module, as-of read indexing, and L1 promotion are sound. Ten concrete defects found that the green 34-test suite does not catch. Most severe: ingest_block ignores getEvents continuation tokens, silently truncating a block's events into immutable, content-addressed epochs (data loss plus cross-provider hash forks — the fixture RPC's own forced 2-event pages would trigger it with >=2-event... >2-event blocks, which the fixture never creates). Other majors: mirror_pull never populates the DB and a subsequent run atomically clobbers the pulled manifest (bootstrap path broken); compat returns false 409 BLOCK_REORGED for canonical hashes absent from the path-dependent seen_heads table (DB rebuild breaks every existing compat client); the client's reorg rewind (cursor discard + note prune) is not crash-atomic with head_etag persistence, permanently stranding phantom notes; a manifest-then-head fetch race with a concurrent epoch cut deletes freshly-cut blocks from the client mirror for one pass (wrong balances/spent flapping); a verify-root mismatch halts epoch cutting forever with no spec-mandated rescan and /health stays OK; and ingest_block's three non-atomic RPC calls can commit mixed-fork rows that hash-based walkback never repairs (with tx_index unwrap_or(0) masking the evidence). Minors: detect_reorg treats RPC outages as reorgs (spurious full-tail rollback and irreversible seen_heads pruning), continuation-token reuse across provider failover plus never persisting the token, and compat's resolve serving reads pinned to un-ingested block numbers.

## Lens: privacy

Privacy-lens review of proto/keyless-indexer (34 tests green, none touched). Four confirmed defects. (1) Compat hardening hole, verified against a live --enable-compat server: every axum-generated rejection (400 bad JSON, 422 deserialize, 415 content-type, 405 method) on /v1/sync/* lacks the spec-mandated X-Strk20-Mode header, and the 422 body echoes the malformed viewing_key value verbatim; the raw router has the same gap for X-Strk20-Privacy. (2) Client sync.db WAL leak, verified experimentally: FeedStore::open chmods the main db to 0600 only after the WAL pragma+DDL have already created sync.db-wal/-shm at 0644; the world-readable WAL demonstrably carries SecretFelt-derived cursor/channel-key material and survives a kill (e.g. Ctrl-C in --watch) at 0644 permanently. (3) --watch re-emits the same 'new note' JSON line on every poll forever (delta filter uses the never-updated initial report.head) and dies on any transient transport error — untested since acceptance only runs one-shot syncs. (4) The acceptance leg f(iii) server-side no-key scan is blind to strk20.db-wal (server running, WAL un-checkpointed at scan time) and to zstd-compressed epoch payloads, and the scanner lacks the Debug-format byte-array encoding. No defects found in FeedTransport request patterns (all GETs are user-invariant; fetch_anchor is never called during sync), and no compat/tracing path logs bodies or cursors (no TraceLayer; with_db warnings carry only rusqlite/public-hash text). Verification probe was a temporary untracked test file, now deleted; working tree clean.

## Lens: client-semantics

Reviewed crates/client (store.rs, sync.rs, verify.rs, main.rs, transport.rs) on proto/keyless-indexer against docs/spec/architecture.md, excluding the deltas already recorded in implementation-notes.md. One critical defect was found and EMPIRICALLY CONFIRMED with a targeted mock-transport experiment against the real FeedStore::apply_feed (scratch test since deleted; tree left clean): when a tail reorg is 'masked' by an epoch cut between two client syncs, apply_feed applies the new epoch via INSERT OR REPLACE without clearing superseded tail rows, and both the tail-delete and the contradiction check look only above the NEW floor — so writes from reorged-away blocks survive forever below the floor (observed: phantom slot value 0x2 at the L1-final checkpoint bound with tail_rewound=false), permanently poisoning the mirror, the checkpoint cursor, and the notes registry (phantom balances and/or permanently missed replacement notes).
